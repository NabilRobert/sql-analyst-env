- **Pass@1:** the share of tries whose submitted query is right on both data copies, averaged per task. **pass^5:** tasks right on all five tries.
- **Mean reward** adds the penalties: -0.5 for a query refused as unsafe, up to -0.1 for queries refused for cost or timed out.
- **Submitted:** tries that called `submit_answer`; an answer given only in text scores 0. **Errored** tries (an infrastructure failure) are left out of every other column.
- The held-out tasks aren't published, so their row can't be rerun by others. Pagila's schema is public and these models have likely seen it; the data copies defeat memorised answers, not knowledge of the schema.

Every run here was measured on MCP-backbone `dd98f06`. The pin then moved to `90fa10d`, which accepts top-level UNION, INTERSECT and EXCEPT (the old pin refused them as unsafe) and refuses row locks (`FOR UPDATE` now counts as unsafe). No try used a row lock and no submitted answer was a set operation, so no pass@1 or pass^5 here would change. Some unsafe counts would: [the rollout review](docs/rollout-review.md#upstream) has the tries.

## Runs over the call limit

Pass rule 2 says no model call may reach 90% of the context window, because past the window Ollama's llama.cpp runner drops the start of the prompt. Qwen3.5 runs on Ollama's MLX runner instead, which ignores `OLLAMA_CONTEXT_LENGTH` although Ollama reports it, so these prompts were processed whole, not cut: the tries saw more context than the rule allows, not less. Held-out runs once, so the run couldn't be redone; Arthur chose to count it, with the breach stated (2026-11-09).

- `qwen3.5:4b`, held-out (private) tasks: 7 tries had a call of 22,118 tokens or more (the longest 56,184). 1 of them was right; counted as wrong, pass@1 would be 62.0%.
